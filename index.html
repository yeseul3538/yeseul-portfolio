프로젝트 01

미납 가맹점 관리 체계 구축

자동이체 출금 방식을 바꾸고, 매달 회수 일정과 추심 기준을 새로 만들었습니다

아이샵케어2024–2026결제 운영
  • 1년간 약 3,600만 원 회수2025–2026 · 월평균 약 300만 원, 최대 월 700만 원
  • 출금할수록 손해 보는 수수료 역전 구간을 미리 찾아 차단잔액 200원 미만 → 최소 출금 단위 1,000원 설정
정책 기획아웃바운드 운영Apps Script
자세히 보기

문제 정의

  • CMS(자동이체 출금)가 실패한 가맹점을 따로 관리하는 방법이 없었습니다. 미납 데이터부터 새로 만들어야 했습니다.
  • CMS는 통장 잔액이 미납금 전체보다 많을 때만 한꺼번에 출금하는 방식이었습니다. 주거래 은행을 바꾸는 등의 이유로 잔액이 모자란 가맹점은 한 푼도 출금되지 않은 채 미납만 쌓였습니다.
  • 지난달 미납을 뒤늦게 챙기는 데 그쳐 장기·고액 미납이 쌓였고, 폐업 후 연락이 끊겨 회수 안내가 닿지 않는 가맹점도 있었습니다.

목표

  • 미납이 쌓인 뒤에야 대응하던 방식을, 출금·회수·추심 단계마다 할 일이 정해진 방식으로 바꾸기

내 역할

  • 출금 정책 분석, 부분 출금 변경안 설계·적용
  • 미납 데이터 구축, 장기·고액·일반 분류 기준 수립
  • 회수 일정 설계, 전화·알림톡·문자 안내 직접 진행
  • 국세청 API와 Apps Script로 휴·폐업 자동 조회 구축

가맹점 문의 응대는 CX팀이 맡았고(응대 매뉴얼 전달), 수수료·세금계산서 처리와 추심 이관 기준은 Finance팀과 협의했습니다.

진행 과정

  1. 정책 진단

    잔액이 미납금 전체보다 많을 때만 출금하는 방식 때문에, 잔액이 적은 가맹점은 한 번도 출금되지 않고 미납만 쌓이고 있었음

  2. 바꾸기 전 손익 계산

    부분 출금으로 바꾸기 전, 잔액 200원 미만에서는 이체 수수료가 출금액보다 커지는 역전 구간 발견 → 최소 출금 단위 1,000원으로 차단. 월 CMS 1,000원 미만 소액 가맹점은 금액대별로 따로 계산해 어디까지 출금할지 정하는 근거로 씀

  3. 감지와 분류

    미납 데이터를 새로 구축하고, 월 약 2,300만 원 규모(2026년 4월 기준)의 미납을 장기·고액·일반으로 분류. 국세청 휴·폐업 자동 조회(30분 주기)로 폐업 가맹점은 따로 관리

  4. 월간 회수 일정

    정상 가맹점은 매월 5·10·14·20·30일 잔액만큼 부분 출금하고, 실패하면 다음 영업일부터 전화·알림톡으로 안내. 휴·폐업 가맹점은 매월 5·15·30일 문자로 안내. 6개월간 입금이 없으면 외부 추심사로 넘기는 기준 수립

  5. 주간 보고

    매주 팀 회의에서 미납·회수 현황을 보고했고, 이 자료가 리더 회의에서 의사결정에 쓰임

구조 도식

결과·산출물

  • 미납금 평균 회수율 8% → 15% (회수율 = 월 회수액 ÷ 월 총 미납금)
  • 1년간(2025–2026) 약 3,600만 원 회수 (월평균 약 300만 원, 최대 월 700만 원)
  • 부분 출금 정책 실제 적용, 최소 출금 단위 1,000원으로 역전 구간 차단
  • 6개월 동안 입금이 없으면 추심사로 넘기는 기준을 정해 팀 전체가 같은 기준으로 처리
  • 주간 미납·회수 보고가 리더 회의의 의사결정 자료로 쓰임

기준점 8%는 미납 데이터를 처음 구축한 뒤 측정한 값으로, 별도 회수 활동 없이 들어온 자연 입금 비율입니다. 15%와의 차이 7%p가 회수 활동으로 늘어난 몫입니다.

배운 점

  • 회수율을 높이려던 부분 출금도 잔액 200원 미만에서는 오히려 손해였습니다. 정책은 바꾸기 전에 금액 구간별로 먼저 계산해 봐야 한다는 걸 이때 배웠습니다.
  • 미납 데이터가 없던 상태라, 회수 일정을 짜기 전에 미납을 장기·고액·일반과 휴·폐업으로 나누는 일부터 했습니다. 나누고 나니 대상마다 안내 방법과 날짜를 다르게 정할 수 있었습니다.

해지·폐업 가맹점 조기 감지와 위약금 재설계

가맹점이 연락하기 전에 폐업을 먼저 찾아 청구하고, 장비를 돌려받도록 위약금 기준을 바꿨습니다

아이샵케어2025계약 운영
  • 해지 위약금 월 순회수액 40만 → 160만 원(4배)놓치던 청구를 찾아낸 만큼 회수도 늘어남
  • 위약금을 장비 잔존가치 기준으로 바꾸고 반납하면 환불목적은 금액보다 장비 회수, 미반납 건만 실제 손실로 청구
  • 전산에 ‘해지’로 잘못 남아 있던 영업 중 가맹점 40여 곳 상태 정정전산 상태를 실제 영업 상태와 맞춤

문제 정의

  • 해지·폐업 가맹점을 따로 챙기는 방법이 없어 CMS·위약금 입금 누락이 반복됐습니다.
  • 국세청 기준으로 정상 영업 중이고 단말기도 쓰고 있는데 전산에는 ‘해지’로 남은 가맹점이 방치돼, 돈이 새고 데이터도 실제와 어긋났습니다.

목표

  • 해지·폐업 가맹점을 일찍 찾아내 CMS·위약금 입금 누락을 막고, 전산 상태를 실제 영업 상태와 맞추기
  • 해지 위약금을 실제 장비 손실에 맞게 산정하기

내 역할

  • 감지, 데이터 대조, 처리 순서 설계, Slack 자동화까지 혼자 기획하고 실행
  • 위약금 재설계는 팀장 승인·법무 검토를 거쳤고, 약관 개정은 계약서 법무를 맡은 Finance팀과 협의

진행 과정

  1. 감지

    CX 상담 내역에서 해지·폐업 문의를 매일 확인하고, 해당 가맹점의 사업자번호로 휴·폐업 조회

  2. 진단

    장비 회수 데이터·국세청·CX 상담 내역을 교차 검증해 문제 건수와 유형을 수치로 파악

  3. 위약금 기준 재설계

    기존 ‘월 CMS × 잔여 개월 수’는 장비를 36개월 모두 쓴다는 전제의 요금이라, 중도 해지 때 실제 장비 손실을 반영하지 못함 → 해지 시점의 감가상각 잔존가치 기준으로 재설계. 장비를 정상 반납하면 위약금을 환불해 손실 보전과 장비 회수를 함께 노림

  4. 접수 자동 기록

    Slack에 올라온 고객 문의에서 이모지 클릭 → 사업자번호 입력 → 문의 링크와 함께 구글 시트에 자동으로 쌓이게 만듦

  5. 담당자 자동 지정

    Slack 자동화로 담당자 지정과 다음 할 일을 정해 두어 같은 누락이 반복되지 않게 함

법인카드 일괄 재발급 도입

문제 정의

  • 법인카드는 가입할 때 전 직원 카드를 한꺼번에 발급하는 경우가 많습니다. 그래서 5년마다 유효기간이 끝나면 기업 단위로 전 직원 카드를 다시 발급해야 했습니다.
  • 일괄 재발급 기능이 없어, 재발급 때마다 직원 1명이 하던 일을 멈추고 카드를 한 장씩 수기로 처리했습니다. 기업 1곳에 4–6시간이 걸렸습니다.

  • 이미 있던 ‘기존 카드 정보 다운로드’ 기능을 활용하는 방법 제안
  • 개발팀과 요구사항 협의, 운영 적용

  1. 진단

    재발급이 얼마나 자주 돌아오는지, 기업 한 곳에 몇 시간이 걸리는지, 누가 붙는지 정리

  2. 근거 정리

    개발 우선순위를 받기 위해 비용을 주기 × 시간 × 인력(1–2주마다 · 기업당 4–6시간 · 담당자 1명이 다른 업무에서 빠짐)으로 정리해 개발 요청 근거로 제시

  3. 요구사항 정의

    실무자가 이미 쓰던 흐름(기존 카드 정보 다운로드 → 그대로 두거나 일부 수정 → 업로드)에 맞춰 일괄 재발급 요구사항 정의

  4. 개발 협업

    개발팀과 요구사항을 협의해 Excel 업로드 기반 일괄 재발급 기능 구현

  5. 적용

    기업 단위 재발급을 업로드 한 번으로 처리하도록 운영 방식을 바꿈

결과·산출물

  • 연간 수작업 약 100–300시간 절감 추정 (연 26–52회 × 기업당 약 3.75–5.75시간)
  • 1–2주마다 빠지던 전담 인력을 상담·운영 업무로 재배치
  • 카드를 한 장씩 입력하던 수기 작업 제거

  • 이미 쓰던 ‘기존 카드 정보 다운로드’ 기능을 활용하니, 처음 쓰는 기능인데도 실무 도입이 수월했습니다.

대량 발급 오류 조기 표시

발급이 끝난 뒤에야 보이던 오류를 처리 도중에 바로 보이게 바꿨습니다

마지막 단계에서야 잡히던 발급 오류조건값으로 처리 중 바로 표시오류 건당 처리 시간 30분–1시간 → 10–20분

현대카드2023개발 협업

문제 정의

  • 법인카드 대량 발급 도중에는 오류를 확인할 수 없어, 마지막 단계에서야 오류 건을 걸러냈습니다.
  • 걸러진 오류 건은 따로 빼 두었다가 수기로 다시 발급해야 했고, 건당 30분–1시간이 걸렸습니다.
  • 고객이 정보를 잘못 입력하는 경우가 많아 오류 비율이 50%를 넘었습니다.
  • 법인카드 시스템은 개인카드 시스템보다 개발 우선순위가 낮아, 개선 요청이 잘 반영되지 않았습니다.

목표

  • 오류를 마지막 단계가 아니라 발급 처리 도중에 확인하게 해, 따로 처리하는 건수 줄이기

내 역할

  • 현업 요청을 핵심 요구·제약·대안으로 나눠 정리
  • 오류 건 수기 재발급 시간을 정리해 개발 필요성 근거로 제시
  • 개발 부담이 적은 대안 제안

진행 과정

  1. 핵심 요구

    ‘오류를 마지막이 아니라 처리 도중에 확인해야 한다’는 요구로 정리

  2. 근거 정리

    낮은 개발 우선순위를 넘기 위해 오류 건 수기 재발급 시간(건당 30분–1시간)을 정리해 제시

  3. 대안 제안

    기존 화면과 단계는 그대로 두고, 발급 정보에 조건값을 걸어 조건에 맞지 않는 데이터를 바로 표시하는 방식 제안

  4. 반영

    화면을 바꾸지 않아 개발 부담이 적은 방식으로 반영

결과·산출물

  • 발급 처리 도중에 오류 건을 바로 확인
  • 오류 건당 처리 시간 30분–1시간 → 10–20분

배운 점

  • 막연한 불편 호소로는 개선 요청이 잘 반영되지 않았습니다. ‘발급 처리 중에 조건에 맞지 않는 건을 바로 표시’처럼 무엇을 바꿀지 적어 가자 개발팀이 검토할 수 있었습니다.
  • 화면을 바꾸지 않는 방법을 같이 낸 것도 도움이 됐습니다. 개발 부담이 줄어드니 우선순위가 낮은 요청이었는데도 반영됐습니다.

출고·계약 데이터 정합성 관리

출고 요청 방식을 하나로 정하고, 출고부터 회수까지 부서별 담당을 정리했습니다

팀마다 따로 관리하던 출고·계약 데이터요청 양식 통일·부서별 담당 정리오출고 건수 80% 이상 감소

아이샵케어2024데이터 정합성

문제 정의

  • 장비 출고·계약서·회계 데이터를 팀마다 따로 관리해 서로 맞지 않았고, 출고 요청 기록이 남지 않아 오출고와 계약서 미수취가 생겼습니다.
  • 임대 장비는 회사 자산이라, 데이터 누락은 회계 감사 때 문제가 될 수 있었습니다.

목표

  • 출고·계약서·회계 데이터가 서로 맞게 하고, 오출고와 감사 때 문제가 될 누락을 미리 막기

내 역할

  • 문제 진단, 출고 요청 양식·시트 자동 기록·48시간 알림(Zapier) 설계
  • R&R로 부서별 책임 정리, SCM·Finance·Commerce팀 협업 조율

진행 과정

  1. 진단

    출고 요청이 기록되지 않아 생긴 오출고·이중 출고와, 고객 요청에 따른 예외 처리가 남지 않아 생긴 데이터 오류 확인

  2. 요청 방식 통일

    출고 요청을 정해진 양식과 순서로만 받도록 바꾸고, 48시간 안에 확인되지 않으면 담당자에게 자동 메일·Slack 알림 (Zapier). 업무 분장표로 출고부터 회수까지 담당 부서 정리

  3. 정기 점검

    매월 출고 내역과 계약서를 크로스체크해 계약서 미수취·오출고·미회수 건을 담당자에게 전달

구조 도식

흐름도 상세보기 ↗

결과·산출물

  • 오출고 건수 80% 이상 감소
  • 오출고·이중 출고의 원인이던 ‘기록 없는 출고 요청’을 막기 위해 요청 양식을 하나로 정하고 시트에 자동으로 쌓이게 함
  • 출고 요청 48시간 미확인 시 담당자 자동 메일·Slack 알림 (Zapier)
  • 매월 출고 내역과 계약서를 대조하는 일을 정기 업무로 만들고, 계약서 미수취·오출고·미회수 건을 담당자에게 전달
  • 출고부터 회수까지 SCM·Finance·Commerce R&R 정리, R&R 흐름도는 신규 입사자 교육 자료로 사용

배운 점

  • 여러 팀이 같은 데이터를 다룰 때는 도구를 붙이기 전에 누가 책임지는지부터 정해야 했습니다.

SOP 01

CMS 관리자 화면 조회 SOP

처음 보는 사람도 같은 칸을 보고 같은 판단을 하도록 만든 한 페이지짜리 조회 매뉴얼

화면 값만 보면 틀리기 쉬운 CMS 상태확인할 칸 별 표시·예외 기준 정리관리자 화면 4개를 한 페이지로

아이샵케어2025운영 문서

문제 정의

  • CMS 관리자 화면에는 가맹점 한 곳마다 계약·청구·납부·세금계산서 항목이 수십 개 있고, 메뉴를 여러 단계 거쳐야 열립니다.
  • 화면에 보이는 값만으로 판단하면 틀리기 쉬운 경우가 있었습니다. 국세청 기준으로 폐업한 가맹점도 미납금이 남아 있으면 CMS는 ‘정상’으로 보입니다.
  • 이런 판단 기준이 문서 없이 담당자의 경험에만 있었습니다.

목표

  • 처음 보는 사람도 메뉴 경로와 별 표시만 따라가면 같은 판단을 내리게 하기
  • 운영에서 판단할 것과 Finance팀에 넘길 것을 문서 안에서 나누기

내 역할

  • 화면별 조회 경로 정리, 확인할 항목 선정
  • 화면 값과 실제 처리가 다른 예외 기준 정리, 문서 작성

문서 설계

  1. 경로부터

    화면마다 메뉴 경로(기본관리 › 회원관리 › 회원상태 › 검색 › 가맹점 선택)를 맨 위 한 줄로 적어, 누가 찾아도 같은 화면에 도착하게 함

  2. 확인할 칸만 표시

    수십 개 항목 중 판단에 쓰는 칸에만 초록 별 표시. 문서 맨 위 규칙은 ‘초록색 별을 확인해 주세요’ 한 줄

  3. 조회 순서대로 배치

    기본 화면 → 검색 → 가맹점 정보 → 납부 상세 내역. 실제로 화면을 여는 순서와 문서 순서를 맞춤

  4. 예외는 따로 모으기

    화면 값과 실제 처리가 다른 경우(폐업인데 CMS 정상, 15일 이후 폐업 등)를 화면 설명과 분리해 맨 아래 ‘자주 묻는 질문’으로 정리

  5. 넘길 곳 표시

    세금계산서 실제 발행 여부처럼 운영에서 판단할 수 없는 항목은 ‘Finance팀 확인 필요’라고 적어, 운영에서 판단할 것과 넘길 것을 나눔

구조 도식

결과·산출물

  • 관리자 화면 4개(기본 화면·검색·가맹점 정보·납부 상세 내역)의 조회 방법을 한 페이지 SOP로 정리
  • 판단에 쓰는 칸 20여 개에만 초록 별을 붙이고, 나머지 칸은 보지 않아도 되게 함
  • 화면 값과 실제 처리가 다른 예외 5가지를 ‘자주 묻는 질문’으로 정리
  • 세금계산서 발행 여부처럼 Finance팀 확인이 필요한 항목을 문서에 표시

원본 SOP는 실제 관리자 화면 캡처로 만들어 가맹점 정보가 들어 있어 새로 제작하였습니다..

배운 점

  • 설명을 더 길게 쓰는 대신 볼 칸을 줄였습니다. 처음 보는 사람은 수십 개 항목 앞에서 어디부터 봐야 할지 모르기 때문입니다.
  • 자주 묻는 질문은 대부분 화면 값과 실제 처리 기준이 다른 곳에서 나왔습니다. 그래서 예외를 화면 설명과 섞지 않고 따로 모았습니다.
SOP 02

구매부터 설치까지 고객 여정 도식

신규 입사자가 회사 일이 어떻게 이어지는지 먼저 알 수 있도록, 고객이 구매부터 설치까지 거치는 단계를 한 장에 그린 교육 자료

고객·외주사·3PL로 이어지는 가입 단계구매 유형·검수·설치 분기까지 연결구매부터 설치까지 15단계를 한 장으로

아이샵케어신규 입사자 교육

문제 정의

  • 가맹점 한 곳이 개통되기까지 고객, 아이샵케어, 외주사, 3PL이 차례로 일을 넘겨받습니다. 신규 입사자는 자기 업무가 이 흐름의 어디쯤인지부터 알아야 했습니다.
  • 구매 유형(개인·법인 × 신규·기가맹)에 따라 필요 서류가 다르고, 서류 검수에서 반려되면 보완 안내 후 다시 접수하는 되돌이 구간이 있습니다.
  • 안내를 보내는 연락처도 단계마다 다릅니다. 신청 링크는 주문자 연락처로, 전자계약은 신청서에 적힌 대표자 연락처로 갑니다.

목표

  • 신규 입사자가 구매부터 설치까지 전체 흐름과 분기를 한 장으로 먼저 이해하게 하기
  • 단계 사이에 무엇이 넘어가는지(연락처, 서류, 장비)까지 보이게 하기

내 역할

  • 구매부터 설치까지 단계와 분기 정리, FigJam 도식 작성
  • 신규 입사자 교육 자료로 제작

장비 출고 단계의 확인 절차는 프로젝트 07(출고·계약 정합성)에서 정리했습니다.

문서 설계

  1. 끝까지 한 장에

    구매 → 서류·계약 → 검수 → 개통·출고 → 설치까지 15단계를 끊지 않고 한 장에 연결

  2. 분기는 맨 앞에

    구매 유형 4가지(개인·법인 × 신규·기가맹)에 따라 필요 서류가 자동으로 정해지는 갈림길을 흐름 맨 앞에 표시

  3. 되돌이 구간 표시

    서류 검수 결과를 PASS·FALSE로 나누고, FALSE면 서류 보완 안내 → 재접수 → 다시 검수로 돌아가는 고리를 따로 그림

  4. 넘기는 정보 표시

    화살표 위에 무엇으로 넘기는지 적음. 신청 링크는 주문자 연락처, 전자계약(모두싸인)은 대표자 연락처

  5. 조건부 경로 구분

    방문설치가 필요한 경우만 다른 색 점선으로 나누고, 출고 D+1 일정 안내 · 장비 도착 D+2 이후 설치 같은 날짜 기준을 함께 적음

구조 도식

결과·산출물

  • 구매부터 설치까지 15단계와 분기 3곳(구매 유형, 서류 검수, 방문설치)을 한 장의 도식으로 정리
  • 단계 사이에 넘기는 정보(주문자·대표자 연락처, 서류, 장비)와 날짜 기준(출고 D+1, 장비 도착 D+2)을 도식 안에 표시
  • 신규 입사자 교육 자료로 제작

배운 점

  • 팀별 업무 설명부터 하지 않고, 고객 한 명이 구매부터 설치까지 거치는 순서대로 그렸습니다. 그래야 신규 입사자가 자기 일 앞뒤에 누가 있는지 알 수 있다고 봤습니다.
  • 서류 보완처럼 되돌아가는 길과 방문설치처럼 일부 고객만 거치는 길은 선 색을 달리했습니다. 한 장에 다 넣어도 기본 순서가 묻히지 않게 하려는 것이었습니다.
