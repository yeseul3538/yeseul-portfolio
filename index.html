프로젝트 01

미납 가맹점 관리 체계 구축

출금 정책 재설계부터 월간 회수 일정·추심 이관까지

쌓이기만 하던 미납부분 출금·월간 회수 일정·추심 이관평균 회수율 8% → 15%

아이샵케어2024–2026결제 운영
  • 미납금 평균 회수율 8% → 15% (기준 8%: 미납 데이터를 처음 구축한 뒤 측정한 자연 입금 비율)
  • 최근 1년 약 3,600만 원 회수 (월평균 약 300만 원, 최대 월 700만 원)
  • 부분 출금 전환 전 수수료 역전 구간(잔액 200원 미만)을 찾아 최소 출금 단위 1,000원으로 차단
정책 기획회수 일정 설계Apps Script
자세히 보기

문제 정의

  • CMS(자동이체 출금) 미납 가맹점을 관리하는 체계가 없어, 미납 데이터부터 새로 구축해야 했습니다.
  • 잔액이 총 미납금 이상일 때만 일괄 출금하는 CMS 방식 때문에, 잔액이 부족한 가맹점의 미납이 회수 없이 계속 쌓였습니다.
  • 전월 미납 고객에 대한 사후 대응에 그쳐 장기·고액 미납이 누적되었고, 폐업 후 연락 두절 같은 회수 사각지대도 있었습니다.

목표

  • 사후 대응에 그치던 미납 관리를, 출금 정책부터 회수·추심까지 이어지는 단계별 체계로 바꾸기

내 역할

  • 출금 정책 분석·부분 출금 변경안 적용
  • 미납 데이터 구축·장기·고액·일반 분류 기준
  • 안내 일정 설계·미납 안내 알림톡 발송
  • 국세청 휴·폐업 자동 조회 Apps Script

가맹점 문의 응대는 CX팀(응대 매뉴얼 전달), 수수료·세금계산서 처리와 추심 이관 기준은 Finance팀과 협의했습니다.

진행 과정

  1. 정책 진단

    잔액이 총 미납금 이상일 때만 출금하는 방식 때문에 저잔액 가맹점의 미납이 회수 없이 쌓이는 구조 확인

  2. 정책 변경과 리스크 검증

    부분 출금 전환 전, 잔액 200원 미만에서 출금액보다 이체 수수료가 커지는 역전 구간 발견 → 최소 출금 단위 1,000원으로 차단. 월 CMS 1천 원 미만 소액 가맹점은 금액대별로 분석해 의사결정 근거 마련

  3. 감지와 분류

    미납 데이터 신규 구축, 2026년 4월 기준 월 약 2,300만 원 규모의 미납을 장기·고액·일반으로 분류. 국세청 휴·폐업 자동 조회(30분 주기)로 폐업 가맹점을 별도 트랙으로 분리

  4. 월간 회수 일정

    출금은 매월 5·10·14·20·30일(잔액만큼 부분 출금), 안내는 매월 5·15·30일. 6개월 미입금 시 외부 추심사 이관 기준 수립

  5. 주간 보고

    매주 팀 위클리 미팅에 미납·회수 현황 보고 → 리더 미팅의 의사결정 자료로 활용

구조 도식

결과·산출물

  • 미납금 평균 회수율 8% → 15% (회수율 = 월 회수액 ÷ 월 총 미납금)
  • 최근 1년 약 3,600만 원 회수 (월평균 약 300만 원, 최대 월 700만 원)
  • 부분 출금 정책 실제 적용, 최소 출금 단위 1,000원으로 역전 구간 차단
  • 6개월 미입금 시 추심사 이관 기준 표준화
  • 주간 미납·회수 현황 보고가 리더 미팅의 의사결정 자료로 활용

기준점 8%: 미납 데이터를 처음 구축한 뒤 측정한 값으로, 별도 회수 활동 없이 들어온 자연 입금 비율입니다.

배운 점

  • 좋은 정책 가설도 엣지 케이스 하나로 손해가 될 수 있어, 수치로 먼저 검증해야 했습니다.
  • 데이터가 없을 때는 기준부터 만들어야 했고, 분류가 명확해야 다음 액션도 명확해졌습니다.

해지·폐업 가맹점 조기 감지와 위약금 재설계

문의를 기다리지 않고 폐업을 먼저 찾아 청구하고, 위약금은 장비 반납을 유도하도록

고객 문의를 기다리던 위약금 청구폐업 조기 감지·교차 검증청구 포착 월 15 → 90건

아이샵케어2025계약 운영
  • 놓치던 해지·폐업 청구 포착 월 15건 → 90건(6배), 이 감지 확대로 해지 위약금 월 순회수액 40만 → 160만 원
  • 위약금 재설계는 금액보다 장비 반납 유도가 목적: 반납하면 환불, 미반납만 실제 손실로 청구
  • 전산상 해지로 잘못 남아 있던 영업 중 가맹점 40여 곳 상태 정정 (데이터 정합성)

문제 정의

  • 해지·폐업 가맹점 트래킹이 부재해 CMS·위약금 입금 누락이 반복되었습니다.
  • 국세청상 사업자가 정상 운영 중이고 단말기 사용도 확인되는데 전산상 해지 처리된 케이스가 방치되어 금전적 손해와 데이터 불일치가 발생했습니다.

목표

  • 해지·폐업 가맹점을 조기에 감지해 CMS·위약금 입금 누락을 막고, 전산 상태를 실제 운영 상태와 일치시키기
  • 해지 위약금을 실제 장비 손실에 맞게 산정하기

내 역할

  • 기획·실행 단독: 감지 → 데이터 크로스 검증 → 프로세스 설계 → Slack 자동화 구축까지 전 과정
  • 위약금 재설계는 팀장 승인·법무 검토를 거쳤고, 약관 개정은 계약서 법무를 맡은 Finance팀과 협의

진행 과정

  1. 감지

    CX 상담 내역 중 해지·폐업 문의 매일 확인, 가맹점 사업자번호 휴·폐업 조회

  2. 진단

    장비 회수 데이터·국세청·CX 상담 내역 크로스 검증, 문제 건수·유형별 케이스 정량 파악

  3. 위약금 구조 재설계

    "월 CMS × 잔여 개월 수" 방식은 장비 36개월 정상 사용을 전제로 한 요금이라 중도 해지 시 실제 장비 손실 미반영 → 해지 시점 감가상각 잔존가치 기준으로 재설계. 장비 정상 반납 시 위약금을 환불해 손실 보전과 장비 회수 유도를 함께 설계

  4. 데이터 자동 적재

    Slack에 공유되는 고객 문의에서 이모지 클릭 → 사업자번호 입력 → 문의 링크와 함께 구글 시트에 자동 적재되는 흐름 구축

  5. 후속 처리 표준화

    Slack 자동화·담당자 지정·후속 작업 표준화로 재발 방지

  • 감지 확대 효과: 놓치던 해지·폐업 청구 월 15건 → 90건(6배). 해지 위약금 월 순회수액 40만 → 160만 원(4배) 증가는 대부분 이 효과입니다.

  • 지속 미납 건은 추심사로 이관하고, 청구 기준 변경에 맞춰 Finance팀과 계약서 상세 약관을 개정해 분쟁 근거 정비
  • 전산상 해지로 잘못 남아 있던 영업 중 가맹점 40여 곳 상태 정정: 청구가 아닌 데이터 정합성 개선 (금전 효과 없음)

문제 정의

  • 법인카드는 최초 가입 시 전 직원 카드를 일괄 발행하는 경우가 많아, 5년마다 유효기간이 만료되면 기업 단위로 전 직원 카드를 한꺼번에 재발급해야 했습니다.
  • 일괄 재발급 시스템이 없어 재발급 시즌마다 직원 1명이 다른 업무에서 빠져 카드를 한 장씩 수기로 처리했습니다 (기업 1곳당 4–6시간).
  • 담당 기업이 많아 이 업무가 1–2주에 한 번꼴로 발생했고, 인력 공백과 수작업 피로가 누적되었습니다.

목표

  • 기업 단위 재발급을 한 번에 처리해, 반복되던 전담 인력 투입을 없애기

내 역할

  • 반복 주기·소요 시간·투입 인력 기준 병목 진단과 비용 환산
  • 실무자가 쓰던 Excel 흐름에 맞춘 요구사항 정의
  • 개발팀과 요구사항 협의·운영 적용

진행 과정

  1. 진단

    반복 주기·소요 시간·투입 인력을 기준으로 건별 수기 처리의 병목 정의

  2. 근거 정리

    개발 우선순위를 얻기 위해 비용을 주기 × 시간 × 인력(1–2주마다 · 기업당 4–6시간 · 담당자 1명이 다른 업무에서 빠짐)으로 정리해 개발 요청의 근거로 제시

  3. 요구사항 정의

    실무자가 이미 쓰는 Excel 흐름(기존 카드 정보 다운로드 → 정보 유지 또는 일부 변경 → 업로드)에 맞춰 일괄 재발급 요구사항 정의

  4. 개발 협업

    개발팀과 요구사항을 협의해 Excel 업로드 기반 일괄 재발급 기능 구현

  5. 적용

    기업 단위 재발급을 업로드 한 번으로 처리하도록 운영 방식 전환

결과·산출물

  • 기업 1곳 재발급 처리 시간 4–6시간 → 15분 (94% 이상 단축)

  • 카드 한 장씩 반복하던 수기 입력 업무 제거
