    사용자 가이드 작성 + 사내 노티 + CX팀 온보딩

Project 02

자산명세서 데이터 확인 프로세스

출고 · 계약서 · 회계 데이터 매칭

Operations · 2024 · 프로세스 설계 · SCM · Finance · Commerce 팀 협업

문제 정의

  • 장비 출고 · 계약서 · 회계 데이터가 각각 다른 팀에서 관리되어 정합성이 무너지고, 백업 부재로 인한 오출고 · 계약서 미수취 등이 발생하였습니다.
  • 임대장비의 경우 회사의 귀속 자산이므로 누락된 데이터로 인해 회계 감사 시에도 문제가 생길 수 있는 상황이었습니다.

Process

  1. 진단

    출고 요청 데이터 적재 부재로 인한 오출고, 이중 출고 등 출고 문제 사항과 고객 요청에 따른 커머스 팀의 임의 처리로 인한 데이터 오류 사항 확인

  2. 표준화

    출고 요청 표준 워크플로우 전환 + 스프레드시트 자동 적재로 담당자 확인 채널 통일화. 48시간 내 담당자 미확인 시 자동 알림 제작

  3. 크로스펀셔널

    RACI Matrix를 통해 출고부터 회수까지 퍼널별 담당자 배정 및 책임부서 문서화

  4. 프로세스 구축

    월간 사이클 출고 ↔ 계약서 크로스체크 프로세스 설계. 계약서 미수취, 장비 오출고, 미회수 등 미비 건 담당자 전달

Scope & Artifacts

  • 출고 요청 워크플로우 도입 + 스프레드시트 자동 백업 시스템 구축
  • SCM · Finance · Commerce 팀 협업 프로세스 설계
  • 정기 크로스체크 루틴 확립 → 자산 명세서 작성 데이터 정합성 증가

Project 04

미납 가맹점 관리

단계별 회수 프로세스 설계 및 보고서 작성

Payment Operations · 2024–2025 · 미납 회수 프로세스 설계 및 실행

문제 정의

  • CMS 미납 가맹점 관리 내용이 부재하여 최초 미납 데이터부터 만들었습니다.
  • 데이터 취합 이후에도 전월 미납 고객에 대한 사후 대응 중심이라 장기 · 고액 미납이 계속 누적되었습니다.
  • 폐업 후 연락 두절과 같은 회수 사각지대 고객이 발생하고 있어 정상 채권 회수가 어려운 구조였습니다.

Process

  1. 감지

    국세청 휴 · 폐업 자동 조회 앱스크립트 제작. 월별 미납자 데이터와 CMS 입금 데이터 매칭으로 미납 / 미납 해소 / 미납 예상 사전 탐지

  2. 분류

    월 기준 약 2,300만 원 규모의 미납 데이터를 장기 · 고액 · 일반으로 분류하여 상황에 맞는 회수 시나리오 매칭

  3. 액션 및 관리

    자동이체 출금일에 맞춰 5일 → 10일 → 14일 → 20일 4단계 Outbound 프로세스 설계. 회수 금액 중 당월 정상 · 미납 출금액 구별 관리

  4. 추심사 이관

    미납 대상자 외부 추심사 이관 기준 및 프로세스 수립. CX팀에 고객 응대 매뉴얼 전달, Finance팀과 추심사 수수료 및 세금계산서 처리 정합성 확보

Scope & Artifacts

  • 미납 사유별 (장기 · 고액 · 폐업 후 미인입) 세분화 목록 관리
  • 미납 기간 및 자동 출금 일자별 Outbound 회수 프로세스 설계
  • 국세청 휴 · 폐업 자동 조회 앱스크립트 도입 (30분 주기 트리거)
  • 6개월 미입금 시 외부 추심사 이관 로직 표준화
  • 미납 발생부터 해소까지 분류별 · 단계별 정합성 높은 데이터 제작

Project 05

CMS 결제 정책 개선

CMS 출금 정책 재설계

Payment Operations · 2024 · 결제 정책 변경 기획

문제 정의

  • 기존 CMS는 고객 통장 잔액이 총 미납금 이상일 때만 일괄 출금하는 방식이었습니다.
  • 잔액이 부족한 가맹점의 미납이 계속 누적되어 정상 회수가 어려운 구조였습니다.

Decision Flow

정책 변경 전 발생할 수 있는 리스크와 엣지케이스를 미리 탐지하고 보완하였습니다..

  1. 관찰 · AS-IS
    분석

    잔액이 총 미납금 이상일 때만 출금하는 기존 방식. 저잔액 가맹점의 미납이 계속 누적되어 정상 회수가 어려운 구조를 확인했습니다.

  2. 가설 · TO-BE
    변경

    잔액이 미납금 이하여도 통장의 잔액을 모두 출금하는 부분 출금 방식으로 바꾸면, 저잔액 구간에서도 회수가 시작되어 미납 비율이 줄어들 것으로 보았습니다.

  3. 반증 · Trade-off
    리스크

    계좌 잔액 200원 미만이면 출금액 < 이체 수수료가 되어 회수할수록 손해인 역전 구간을 발견했습니다.

  4. 결론 · Decision
    보완

    ① 최소 출금 단위를 설정해 역전 구간을 차단하고, ② 월 CMS 1천 원 미만 소액 가맹점을 리스트업해 금액대별 비율을 분석, 의사결정 근거 데이터를 만들었습니다.

Scope & Artifacts

  • CMS 출금 정책 변경안 도출
  • 정책 변경으로 인한 리스크 사전 분석 및 액션 플랜 도출
