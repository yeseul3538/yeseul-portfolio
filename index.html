  • 해지 · 폐업 장비의 감가상각을 실제 계산해 운영 기준에 반영
  • 가맹점 안내 · 진행 프로세스 표준화
크로스 검증Slack 자동화

문제 정의

  • 해지 · 폐업 가맹점 트래킹이 부재해 CMS · 위약금 입금 누락이 반복되었습니다.
  • 국세청상 사업자가 정상 운영 중이고 단말기 사용도 확인되는데 전산상 해지 처리된 케이스가 방치되어 금전적 손해와 데이터 불일치가 발생했습니다.

목표

  • 해지·폐업 가맹점을 조기에 감지해 CMS · 위약금 입금 누락을 막고, 전산 상태를 실제 운영 상태와 일치시키기

내 역할

  • 단독 진행 — 감지 → 데이터 크로스 검증 → 프로세스 설계 → Slack 자동화 구축까지 전 과정

진행 과정

  1. 감지

    CX 상담 내역 중 해지 / 폐업 문의 매일 확인, 가맹점 사업자번호 휴 · 폐업 조회

  2. 진단

    장비 회수 데이터 + 국세청 + CX 상담 내역 크로스 검증, 문제 건수 · 유형별 케이스 정량 파악

  3. 설계

    고객 여정 시작부터 끝까지 퍼널별 데이터가 한 번의 입력으로 자동 적재되는 프로세스 구축

  4. 프로세스 구축

    Slack 자동화 + 담당자 지정 + 후속 작업 표준화로 재발 방지

효과

  • 해지 · 폐업 장비의 감가상각을 실제 계산해 운영 기준에 반영
  • 퍼널별 데이터 자동 적재 프로세스 구축 → 누락 재발 방지
  • 가맹점 안내 및 진행 프로세스 표준화

배운 점

  • 한 가지 데이터만으로는 상태를 판단할 수 없고, 여러 출처를 교차해야 실제 문제가 보였습니다.
  • 사후 대응보다 감지 시점을 앞당기는 것이 손실을 줄였습니다.

문제 정의

  • CMS 미납 가맹점 관리 체계가 없어 최초 미납 데이터부터 만들었습니다.
  • 데이터 취합 이후에도 전월 미납 고객에 대한 사후 대응 중심이라 장기 · 고액 미납이 계속 누적되었습니다.
  • 폐업 후 연락 두절 등 회수 사각지대 고객이 발생해 정상 채권 회수가 어려운 구조였습니다.

목표

  • 사후 대응 중심의 미납 관리를 사전 탐지 · 유형별 회수 체계로 전환하기

내 역할

  • 미납 데이터 최초 구축, 분류 기준 · 4단계 Outbound 설계
  • 국세청 휴 · 폐업 자동 조회 Apps Script 제작
  • CX · Finance와 추심 이관 프로세스 수립
  • 자동화 도구: Google Apps Script · Zapier

진행 과정

  1. 감지

    국세청 휴 · 폐업 자동 조회 Apps Script 제작. 월별 미납 데이터와 CMS 입금 데이터 매칭으로 미납 / 해소 / 예상 사전 탐지

  2. 분류

    월 약 2,300만 원 규모의 미납 데이터를 장기 · 고액 · 일반으로 분류해 상황별 회수 시나리오 매칭

  3. 액션 및 관리

    자동이체 출금일에 맞춰 5일 → 10일 → 14일 → 20일 4단계 Outbound 설계. 회수 금액 중 당월 정상 · 미납 출금액 구별 관리

  4. 추심사 이관

    외부 추심사 이관 기준 및 프로세스 수립. CX팀 응대 매뉴얼 전달, Finance팀과 수수료 · 세금계산서 처리 정합성 확보

Scope & Artifacts

  • 미납금 회수율 8% → 15% 개선
  • 미납 사유별 (장기 · 고액 · 폐업 후 미인입) 세분화 목록 관리
  • 미납 기간 및 자동 출금 일자별 Outbound 회수 프로세스 설계
  • 국세청 휴 · 폐업 자동 조회 Apps Script 도입 (30분 주기 트리거)
  • 6개월 미입금 시 외부 추심사 이관 로직 표준화
  • 미납 발생부터 해소까지 분류별 · 단계별 데이터 제작

배운 점

  • 데이터가 없을 때는 기준부터 만들어야 했습니다.
  • 분류가 명확해야 다음 액션도 명확해졌습니다.

문제 정의

  • 고객 측 계약 해지 시 위약금 부과가 진행되어야 하나 계약서 버전별로 위약금 산정식에 차이가 있었습니다.
  • 계약서 디벨롭을 진행하며 우선 Google Sheet 계산기를 만들어 배포하였습니다.
  • 늘어나는 CX 문의와 다양해지는 계약 내용으로 Google Sheet 수기 진행에 병목이 발생하였습니다.

  • 계약서 버전별로 다른 산정식을 하나의 툴로 통합해, 누가 계산해도 같은 결과가 나오게 하기

진행 과정

  1. 계약내용 분해

    3-Step UI (계약유형 → 메인 → 추가장비)로 분기 명세화

  2. 개발 명세서 작성

    4가지 조건별 산정식 · 부가세 처리 분기를 명세서로 정리해 개발자에게 전달

  3. QA

    1차 빌드 검증 → 11건 보완 요구사항 도출 (미설치 케이스 / 설치비 추가 청구 등)

  4. 배포

    사용자 가이드 작성 + 사내 노티 + CX팀 온보딩

Scope & Artifacts

  • 4가지 계약 유형 통합 (오프라인 · 온라인 초회 · 온라인 갱신 · 케어서비스)
  • 11건 QA 보완 요구사항 도출 및 반영
  • 부가세 처리 분기 표준화 · 사용자 가이드 작성 · 사내 배포 완료

배운 점

  • 조건을 개발자가 구현할 수 있는 수준까지 쪼개는 것이 기획의 핵심이었습니다.
  • 엣지 케이스는 실제 빌드를 검증하면서 드러났습니다.

CMS 결제 정책 개선

CMS 출금 정책 재설계

Payment Operations · 2024 · 정책 기획
  • 일괄 출금 → 부분 출금 방식으로 정책 변경 · 실제 적용
  • 저잔액 케이스 이체 수수료 역전 리스크 사전 분석 및 액션 플랜 도출
정책 기획트레이드오프
자세히 보기 →

문제 정의

  • 기존 CMS는 고객 통장 잔액이 총 미납금 이상일 때만 일괄 출금하는 방식이었습니다.
  • 잔액이 부족한 가맹점의 미납이 계속 누적되어 정상 회수가 어려운 구조였습니다.

목표

  • 저잔액 가맹점도 회수가 시작되도록 출금 정책을 바꾸되, 변경 전에 리스크부터 검증하기

내 역할

  • AS-IS 분석 · 변경안 도출 · 적용
  • 수수료 역전 구간 발견 → 최소 출금 단위 · 소액 가맹점 분석 등 보완책 마련

판단 흐름

정책 변경 전 발생할 수 있는 리스크와 엣지케이스를 미리 탐지하고 보완하였습니다.

  1. 관찰 · AS-IS
    분석

    잔액이 총 미납금 이상일 때만 출금하는 기존 방식에서 저잔액 가맹점의 미납이 계속 누적되는 구조를 확인했습니다.

  2. 가설 · TO-BE
    변경

    잔액이 미납금 이하여도 잔액을 모두 출금하는 부분 출금 방식이면 저잔액 구간에서도 회수가 시작되어 미납 비율이 줄어들 것으로 보았습니다.

  3. 반증 · Trade-off
    리스크

    계좌 잔액 200원 미만이면 출금액 < 이체 수수료가 되어 회수할수록 손해인 역전 구간을 발견했습니다.

  4. 결론 · Decision
    보완

    ① 최소 출금 단위를 설정해 역전 구간을 차단하고, ② 월 CMS 1천 원 미만 소액 가맹점을 리스트업해 금액대별 비율을 분석, 의사결정 근거 데이터를 만들었습니다.

Scope & Artifacts

  • CMS 부분 출금 정책 변경안 도출 및 실제 적용
  • 정책 변경으로 인한 리스크 사전 분석 및 액션 플랜 도출

배운 점

  • 좋은 가설도 엣지 케이스 하나로 뒤집힐 수 있었습니다.
  • 정책은 수치로 먼저 검증한 뒤 제안해야 설득력이 생겼습니다.

법인카드 재발급 일괄 처리

건별 수기 재발급 → Excel 업로드 일괄 처리 전환

Operations · 2023 · 프로세스 설계
  • 기업 1곳 재발급 처리 시간 4–6시간 → 15분 (90% 이상 단축)
  • 1–2주마다 반복되던 담당자 1명 전담 업무를 해소해 팀 리소스 확보
  • 카드 정보 다운로드 → 수정 → 일괄 업로드로 재발급 흐름 표준화
업무 자동화개발 협업프로세스 설계
자세히 보기 →

문제 정의

  • 법인카드는 최초 가입 시 전 직원 카드를 일괄 발행하는 경우가 많아, 5년마다 유효기간이 만료되면 기업 단위로 전 직원 카드를 한꺼번에 재발급해야 했습니다.
  • 일괄 재발급 시스템이 없어 재발급 시즌마다 직원 1명이 다른 업무에서 빠져 카드를 한 장씩 수기로 처리했습니다 (기업 1곳당 4–6시간).
  • 법인카드 사용률 국내 2위로 담당 기업이 많아 이 업무가 1–2주에 한 번꼴로 발생했고, 인력 공백과 수작업 피로가 누적되었습니다.

목표

  • 기업 단위 재발급을 한 번에 처리해, 반복되던 전담 인력 투입을 없애기

내 역할

  • 반복 주기 · 소요 시간 · 투입 인력 기준으로 병목 진단
  • 다운로드 → 수정 → 업로드 흐름 정의, 개발팀과 요구사항 협의 · 운영 적용

진행 과정

  1. 진단

    반복 주기 · 소요 시간 · 투입 인력을 기준으로 건별 수기 처리의 병목 정의

  2. 흐름 설계

    기존 카드 정보 Excel 다운로드 → 정보 유지 또는 일부 변경 → 시스템 업로드로 이어지는 재발급 흐름 정의

  3. 개발 협업

    개발팀과 협업해 Excel 업로드 기반 일괄 재발급 프로세스 개발

  4. 적용

    기업 단위 재발급을 업로드 한 번으로 처리하도록 운영 방식 전환

효과

  • 기업 1곳 재발급 처리 시간 4–6시간 → 15분
  • 1–2주 주기로 발생하던 전담 인력 투입 해소 → 상담 · 운영 업무에 리소스 재배치
  • 카드 한 장씩 반복하던 수기 입력 업무 제거 → 작업 피로도 해소

배운 점

  • 비용을 주기 × 시간 × 인력으로 수치화하니 개선의 필요성을 설득하기 쉬웠습니다.
  • 실무자가 이미 쓰는 도구(Excel)의 흐름에 맞추니 도입이 수월했습니다.
