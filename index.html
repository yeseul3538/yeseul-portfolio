미납 가맹점 관리 체계 구축

출금 정책 재설계부터 월간 회수 일정·추심 이관까지

회수 없이 쌓이던 미납부분 출금·월간 회수 일정·추심 기준평균 회수율 8% → 15%

아이샵케어2024–2026결제 운영
  • 미납금 평균 회수율 8% → 15%8%는 회수 활동 없이 들어오던 자연 입금 비율
  • 1년간 약 3,600만 원 회수2025–2026 · 월평균 약 300만 원, 최대 월 700만 원
  • 출금할수록 손해 보는 수수료 역전 구간을 미리 찾아 차단잔액 200원 미만 → 최소 출금 단위 1,000원 설정
정책 기획아웃바운드 운영Apps Script
자세히 보기

문제 정의

  • CMS(자동이체 출금) 미납 가맹점을 관리하는 체계가 없었습니다. 미납 데이터부터 새로 만들어야 했습니다.
  • CMS는 통장 잔액이 미납금 전체보다 많을 때만 한꺼번에 출금하는 방식이었습니다. 주거래 은행을 바꾸는 등의 이유로 잔액이 모자란 가맹점은 한 푼도 출금되지 않은 채 미납만 쌓였습니다.
  • 전월 미납에 대한 사후 대응에 그쳐 장기·고액 미납이 누적됐고, 폐업 후 연락이 끊긴 가맹점처럼 회수가 닿지 않는 사각지대도 있었습니다.

목표

  • 사후 대응뿐이던 미납 관리를 출금 정책 → 회수 → 추심으로 이어지는 단계별 체계로 바꾸기

내 역할

  • 출금 정책 분석, 부분 출금 변경안 설계·적용
  • 미납 데이터 구축, 장기·고액·일반 분류 기준 수립
  • 회수 일정 설계, 전화·알림톡·문자 안내 직접 진행
  • 국세청 API와 Apps Script로 휴·폐업 자동 조회 구축

가맹점 문의 응대는 CX팀이 맡았고(응대 매뉴얼 전달), 수수료·세금계산서 처리와 추심 이관 기준은 Finance팀과 협의했습니다.

진행 과정

  1. 정책 진단

    잔액이 미납금 전체보다 많을 때만 출금하는 방식 때문에, 잔액이 적은 가맹점의 미납이 회수 없이 쌓이는 구조 확인

  2. 정책 변경과 리스크 검증

    부분 출금으로 바꾸기 전, 잔액 200원 미만에서는 이체 수수료가 출금액보다 커지는 역전 구간 발견 → 최소 출금 단위 1,000원으로 차단. 월 CMS 1,000원 미만 소액 가맹점은 금액대별로 따로 분석해 의사결정 근거 마련

  3. 감지와 분류

    미납 데이터를 새로 구축하고, 월 약 2,300만 원 규모(2026년 4월 기준)의 미납을 장기·고액·일반으로 분류. 국세청 휴·폐업 자동 조회(30분 주기)로 폐업 가맹점은 별도 트랙으로 분리

  4. 월간 회수 일정

    정상 가맹점은 매월 5·10·14·20·30일 잔액만큼 부분 출금하고, 실패하면 다음 영업일부터 전화·알림톡으로 안내. 휴·폐업 가맹점은 매월 5·15·30일 문자로 안내. 6개월간 입금이 없으면 외부 추심사로 넘기는 기준 수립

  5. 주간 보고

    매주 팀 위클리 미팅에서 미납·회수 현황 보고 → 리더 미팅의 의사결정 자료로 사용

구조 도식

결과·산출물

  • 미납금 평균 회수율 8% → 15% (회수율 = 월 회수액 ÷ 월 총 미납금)
  • 1년간(2025–2026) 약 3,600만 원 회수 (월평균 약 300만 원, 최대 월 700만 원)
  • 부분 출금 정책 실제 적용, 최소 출금 단위 1,000원으로 역전 구간 차단
  • 6개월 미입금 시 추심사 이관 기준 표준화
  • 주간 미납·회수 현황 보고가 리더 미팅의 의사결정 자료로 쓰임

기준점 8%는 미납 데이터를 처음 구축한 뒤 측정한 값으로, 별도 회수 활동 없이 들어온 자연 입금 비율입니다. 15%와의 차이 7%p가 회수 체계로 늘어난 몫입니다.

배운 점

  • 회수율을 높이려던 부분 출금도 잔액 200원 미만에서는 오히려 손해였습니다. 정책은 바꾸기 전에 금액 구간별로 먼저 계산해 봐야 한다는 걸 이때 배웠습니다.
  • 미납을 장기·고액·일반으로, 휴·폐업은 별도 트랙으로 나누고 나서야 대상별 안내 방법과 일정을 정할 수 있었습니다. 데이터가 없을 때는 분류 기준을 세우는 일이 먼저였습니다.

해지·폐업 가맹점 조기 감지와 위약금 재설계

문의가 오기 전에 폐업을 먼저 찾아 청구하는 감지 체계와, 장비 반납을 끌어내는 위약금 구조

고객 문의만 기다리던 위약금 청구폐업 조기 감지·교차 검증월 청구 15 → 90건

아이샵케어2025계약 운영
  • 놓치던 해지·폐업 청구 월 15건 → 90건(6배)이 덕분에 해지 위약금 월 순회수액 40만 → 160만 원
  • 위약금을 장비 잔존가치 기준으로 바꾸고 반납하면 환불목적은 금액보다 장비 회수, 미반납 건만 실제 손실로 청구
  • 전산에 ‘해지’로 잘못 남아 있던 영업 중 가맹점 40여 곳 상태 정정전산 데이터를 실제 영업 상태와 일치

문제 정의

  • 해지·폐업 가맹점을 추적하는 체계가 없어 CMS·위약금 입금 누락이 반복됐습니다.
  • 국세청 기준으로 정상 영업 중이고 단말기도 쓰고 있는데 전산에는 ‘해지’로 남은 가맹점이 방치돼, 돈이 새고 데이터도 실제와 어긋났습니다.

목표

  • 해지·폐업 가맹점을 일찍 찾아내 CMS·위약금 입금 누락을 막고, 전산 상태를 실제 영업 상태와 맞추기
  • 해지 위약금을 실제 장비 손실에 맞게 산정하기

내 역할

  • 기획·실행 단독: 감지 → 데이터 교차 검증 → 프로세스 설계 → Slack 자동화 구축
  • 위약금 재설계는 팀장 승인·법무 검토를 거쳤고, 약관 개정은 계약서 법무를 맡은 Finance팀과 협의

진행 과정

  1. 감지

    CX 상담 내역에서 해지·폐업 문의를 매일 확인하고, 해당 가맹점의 사업자번호로 휴·폐업 조회

  2. 진단

    장비 회수 데이터·국세청·CX 상담 내역을 교차 검증해 문제 건수와 유형을 수치로 파악

  3. 위약금 구조 재설계

    기존 ‘월 CMS × 잔여 개월 수’는 장비를 36개월 모두 쓴다는 전제의 요금이라, 중도 해지 때 실제 장비 손실을 반영하지 못함 → 해지 시점의 감가상각 잔존가치 기준으로 재설계. 장비를 정상 반납하면 위약금을 환불해 손실 보전과 장비 회수를 함께 노림

  4. 데이터 자동 적재

    Slack에 올라온 고객 문의에서 이모지 클릭 → 사업자번호 입력 → 문의 링크와 함께 구글 시트에 자동 적재되는 흐름 구축

  5. 후속 처리 표준화

    Slack 자동화로 담당자 지정과 후속 작업을 표준화해 같은 누락이 반복되지 않게 함

문제 정의

  • 장비 출고·계약서·회계 데이터를 팀마다 따로 관리해 서로 맞지 않았고, 출고 요청 기록이 남지 않아 오출고와 계약서 미수취가 생겼습니다.
  • 임대 장비는 회사 자산이라, 데이터 누락은 회계 감사 때 문제가 될 수 있었습니다.

목표

  • 출고·계약서·회계 데이터를 하나의 기준으로 맞추고, 오출고와 자산 감사 리스크를 미리 막기

내 역할

  • 문제 진단, 출고 워크플로우·자동 적재·48시간 알림(Zapier) 설계
  • R&R로 부서별 책임 정리, SCM·Finance·Commerce팀 협업 조율

진행 과정

  1. 진단

    출고 요청이 기록되지 않아 생긴 오출고·이중 출고와, 고객 요청에 따른 예외 처리가 남지 않아 생긴 데이터 오류 확인

  2. 표준화

    출고 요청을 표준 워크플로우로 전환하고, 48시간 안에 확인되지 않으면 담당자에게 자동 메일·Slack 알림 (Zapier). 업무 분장표로 출고부터 회수까지 담당 부서 정리

  3. 정기 점검

    매월 출고 내역과 계약서를 크로스체크해 계약서 미수취·오출고·미회수 건을 담당자에게 전달
